# 并发限制替代策略实现总结

## 实现概述

根据性能测试结果，我们发现默认的FailFast策略在高并发场景下会导致大量503错误。因此，我们实现了一个更友好的超时排队策略。

## 完成的修改

### 1. 新增 TimeoutQueueStrategy (超时排队策略)

**文件**: `renderer/chrome.go`

实现了新的并发控制策略，支持请求排队等待：

```go
type TimeoutQueueStrategy struct {
    sem       chan struct{}
    queueSize int
    timeout   time.Duration
}
```

**特性**:
- 当并发数达到上限时，新请求进入队列等待
- 最多等待 `RENDERER_QUEUE_TIMEOUT` (默认5秒)
- 超时后返回503错误
- 队列大小可配置（默认8）

### 2. 扩展配置支持

**文件**: `config/config.go`

新增以下配置项：

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `RENDERER_QUEUE_SIZE` | 8 | 队列大小 |
| `RENDERER_QUEUE_TIMEOUT` | 5s | 排队超时时间 |
| `RENDERER_OVERLOAD_STRATEGY` | queue | 过载策略 (failfast/queue) |

### 3. 更新主服务逻辑

**文件**: `main.go`

根据 `RENDERER_OVERLOAD_STRATEGY` 环境变量选择不同的策略：

```go
switch cfg.Renderer.OverloadStrategy {
case "failfast":
    overloadStrategy = renderer.NewFailFastStrategy(maxConcurrent)
case "queue":
    overloadStrategy = renderer.NewTimeoutQueueStrategy(maxConcurrent, cfg.Renderer.QueueSize, cfg.Renderer.QueueTimeout)
}
```

添加了详细的并发控制与过载策略章节，包括：
- 两种策略的对比

- 环境变量说明

## 测试验证

### 测试场景
- 并发限制: 2
- 队列大小: 2
- 队列超时: 2秒
- 测试方法: 同时发送3个请求（超过并发限制）

### 测试结果
```
请求1: HTTP 200, 响应时间: 4.209623s  (排队等待后成功)
请求2: HTTP 200, 响应时间: 4.208569s  (排队等待后成功)
请求3: HTTP 503, 响应时间: 0.012000s (队列满，被拒绝)
```

### 结论
新的队列策略有效工作：
- ✅ 请求1和2成功排队并处理
- ⚠️ 请求3因队列满被拒绝
- ✅ 排队机制减少了立即失败的请求数量

## 推荐配置

### 适合中等并发场景
```bash
RENDERER_OVERLOAD_STRATEGY=queue
MAX_CONCURRENT=16
RENDERER_QUEUE_SIZE=16
RENDERER_QUEUE_TIMEOUT=3s
```

### 适合高并发场景
```bash
RENDERER_OVERLOAD_STRATEGY=queue
MAX_CONCURRENT=32
RENDERER_QUEUE_SIZE=32
RENDERER_QUEUE_TIMEOUT=5s
```

### 适合低并发场景（可快速失败）
```bash
RENDERER_OVERLOAD_STRATEGY=failfast
MAX_CONCURRENT=8
```

## 性能对比

| 策略 | 特点 | 适用场景 |
|------|------|----------|
| FailFast | 立即拒绝，响应快 | 低延迟要求，客户端可重试 |
| TimeoutQueue | 排队等待，用户友好 | 高峰流量，服务端控制队列 |

## 后续优化建议
