# LaTeX 渲染服务性能测试计划

## 1. 测试目标

### 主要目标
- 测定服务在不同并发场景下的性能表现
- 找到服务能够稳定处理的最大并发请求数
- 评估缓存机制对性能的影响
- 为生产环境部署提供性能基准数据

### 关键指标
- **吞吐量**: QPS (每秒请求数)
- **响应时间**: 平均响应时间、P95、P99响应时间
- **成功率**: 成功请求的百分比
- **资源利用**: CPU、内存使用情况
- **错误率**: 不同错误类型的分布

## 2. 测试环境

### 系统环境
- **操作系统**: Linux 5.10.134-19.1.al8.x86_64
- **容器**: Docker
- **部署方式**: 单实例部署

### 服务配置
- **端口**: 8080
- **并发限制**: 2 (默认)
- **渲染超时**: 30s
- **缓存类型**: 本地文件系统
- **预热**: 已启用 (Chrome浏览器预启动)

### 测试工具
- **Apache Bench (ab)**: 主要压力测试工具
- **wrk**: 备用高性能测试工具
- **curl**: 基础请求测试

## 3. 测试场景设计

### 场景1: 基准测试 (默认并发数2)
**目的**: 建立性能基准线

| 并发数 | 总请求数 | 公式类型 | 缓存状态 |
|--------|----------|----------|----------|
| 2 | 100 | E=mc^2 | 冷启动(无缓存) |
| 2 | 100 | E=mc^2 | 热启动(有缓存) |

### 场景2: 并发递增测试
**目的**: 找到服务性能拐点

| 测试批次 | 并发数 | 总请求数 | 公式类型 | 预期 |
|----------|--------|----------|----------|------|
| 1 | 4 | 200 | E=mc^2 | 测试默认并发4 |
| 2 | 8 | 400 | E=mc^2 | 轻微性能下降 |
| 3 | 16 | 800 | E=mc^2 | 继续观察 |
| 4 | 32 | 1600 | E=mc^2 | 开始出现错误 |
| 5 | 64 | 3200 | E=mc^2 | 接近极限 |
| 6 | 128 | 6400 | E=mc^2 | 超过极限 |
| 7 | 256 | 12800 | E=mc^2 | 严重过载 |
| 8 | 512 | 25600 | E=mc^2 | 极限测试 |
| 9 | 1000 | 50000 | E=mc^2 | 破坏性测试 |

### 场景3: 复杂公式测试
**目的**: 测试不同复杂度对性能的影响

| 并发数 | 总请求数 | 公式类型 | 复杂度描述 |
|--------|----------|----------|------------|
| 16 | 800 | \int_{0}^{\infty} e^{-x^2} dx | 中等复杂度 |
| 16 | 800 | \sum_{n=1}^{\infty} \frac{1}{n^2} = \frac{\pi^2}{6} | 高复杂度 |
| 16 | 800 | \begin{matrix} a & b \\ c & d \end{matrix} | 矩阵 |

### 场景4: 混合请求测试
**目的**: 模拟真实生产环境

| 公式类型 | 比例 | 缓存状态 |
|----------|------|----------|
| E=mc^2 | 70% | 缓存命中 |
| 复杂公式 | 20% | 冷启动 |
| 随机公式 | 10% | 部分缓存 |

## 4. 测试用例

### 测试用例1: 冷启动性能
```bash
# 清理缓存
rm -rf ./cache/*

# 执行测试
ab -n 100 -c 2 "http://localhost:8080/api?latex=E=mc^2"

# 记录指标
- 响应时间
- 成功率
- 错误分布
```

### 测试用例2: 热启动性能
```bash
# 确保缓存已存在
ls ./cache/ | wc -l

# 执行测试
ab -n 1000 -c 50 "http://localhost:8080/api?latex=E=mc^2"

# 记录指标
- QPS提升
- 响应时间改善
- 缓存命中率
```

### 测试用例3: 并发极限测试
```bash
# 递增并发测试
for concurrency in 4 8 16 32 64 128 256 512 1000; do
  echo "Testing with concurrency: $concurrency"
  ab -n $((concurrency * 100)) -c $concurrency "http://localhost:8080/api?latex=E=mc^2" \
    > results/concurrency_${concurrency}.txt 2>&1
  sleep 5
done
```

### 测试用例4: 不同公式复杂度测试
```bash
# 简单公式
ab -n 500 -c 16 "http://localhost:8080/api?latex=E=mc^2"

# 复杂公式
ab -n 500 -c 16 "http://localhost:8080/api?latex=\int_{0}^{\infty}%20e^{-x^2}%20dx"

# 矩阵公式
ab -n 500 -c 16 "http://localhost:8080/api?latex=\begin{matrix}%20a%20&%20b%20\\\\%20c%20&%20d%20\end{matrix}"
```

## 7. 风险评估

### 高风险
- **服务崩溃**: 超过极限并发可能导致服务不可用
- **内存溢出**: 大量并发可能导致OOM
- **测试环境不稳定**: CI/CD环境可能影响结果准确性

### 缓解措施
- 逐步增加并发数，避免一次性过载
- 设置合理的超时时间
- 在测试间隔期间监控服务状态
- 如服务崩溃，立即停止测试并重启
