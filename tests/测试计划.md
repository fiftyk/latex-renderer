# LaTeX Renderer 并发测试计划

## 1. 测试目标

验证 LaTeX Renderer 服务的:
- 并发处理能力是否符合配置预期
- 并发满载时的 FailFast 策略是否正常工作
- 重试机制在渲染失败时是否按预期触发

## 2. 服务关键配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| MAX_CONCURRENT | 2 | 最大并发渲染请求数 |
| maxRequests | 10 | 每10个请求后重启浏览器 |
| maxInterval | 5分钟 | 每5分钟重启浏览器 |
| 渲染超时 | 10秒 | 单次渲染最大等待时间 |
| 重试次数 | 2次 | 渲染失败最多重试2次 |

## 3. 测试场景

### 3.1 场景一：基础功能测试
- 单个请求正常渲染
- 验证服务健康检查接口

### 3.2 场景二：并发限制测试
- 同时发送 2 个请求（等于限制）- 应全部成功
- 同时发送 3 个请求（超过限制）- 应有 1 个返回 503
- 同时发送 5 个请求 - 应有 3 个返回 503

### 3.3 场景三：FailFast 策略验证
- 并发满载时，新请求应立即返回 503，不应排队等待
- 响应体应包含错误信息 "服务繁忙，请稍后再试"

### 3.4 场景四：持续压力测试
- 持续发送请求，验证服务稳定性
- 观察浏览器重启机制是否正常

## 4. 测试工具

使用 `ab` (Apache Benchmark) 或 `curl` 并行请求进行测试

## 5. 测试步骤


## 6. 预期结果

| 测试场景 | 预期结果 |
|----------|----------|
| 2个并发 | 100% 成功 |
| 3个并发 | 66% 成功，33% 返回 503 |
| 5个并发 | 40% 成功，60% 返回 503 |
| 503响应时间 | < 100ms（快速失败） |

## 7. 验收标准

- [ ] 并发数不超过配置值
- [ ] 超过限制时返回 503 状态码
- [ ] 503 响应时间 < 100ms
- [ ] 服务在压力测试后仍可正常运行
